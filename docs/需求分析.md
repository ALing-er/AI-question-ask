## 1. 一句话定位

### 已落地的红线

1. **管理员不可见聊天内容** —— 不是 UI 隐藏，是**根本不提供该接口**。
2. **管理员不能对自己执行禁用/删除/重置密码**，也不能删除管理员账号。
3. **角色固定** —— 注册一律 `user`；管理员只来自 `.env` 种子账号，界面无提权入口。
4. **权限在服务端校验** —— 前端隐藏按钮只是体验优化。

## 5. 核心流程

### 5.1 注册 / 登录

```
POST /api/auth/register  {username, password}
  → 检查 ALLOW_REGISTRATION 开关
  → 格式校验（用户名 3-20 位字母数字下划线；密码 ≥8）
  → 唯一性校验（唯一索引兜底并发）
  → bcrypt 哈希 → 落库(role=user, status=active, token_version=0)
  → 写审计日志 → 直接签发 JWT（注册即登录）

POST /api/auth/login
  → 用户不存在 与 密码错误 统一返回 401（防用户名枚举）
  → 锁定未过期 → 429 AUTH_LOGIN_LOCKED
  → 密码错误 → 失败计数 +1；达到 5 次锁定 15 分钟
  → 被禁用返回 403 AUTH_USER_DISABLED
  → 成功 → 清空失败计数、更新 last_login_at、写审计 → 签发 JWT
```

JWT payload：`sub` / `role` / `ver` / `jti` / `iat` / `exp`，有效期 7 天。

### 5.2 流式对话（含降级）

```
POST /api/chat/stream  {conversation_id, content, model_id?, web_search?}
  → 校验内容非空且不超过 MAX_MESSAGE_CHARS
  → 校验会话归属（非本人 404）
  → 校验主模型可解析（不可解析直接 404）
  → 用户消息落库 + 首条消息自动生成标题 + 刷新会话 updated_at
  → 系统提示词 = 会话 system_prompt，否则 DEFAULT_SYSTEM_PROMPT
  → 组装上下文（系统提示词 + 历史摘要 + 最近 10 轮，按估算 token 预算约束）
  → 按 fallback 链依次尝试打开上游流：
        web_search && 该模型支持搜索 → 请求体带 enable_search + search_options
        第一个 chunk 到手 → 选定该模型
        失败（连接/超时/429/密钥/未开通） → 试下一个
  → 建 assistant 占位消息(status=streaming) → 发 meta
  → 逐 chunk 转 SSE 下发（delta / reasoning）
  → 结束回写同一条消息（content + reasoning + tokens + latency）
```

补充：`meta.model_id` 是实际使用的模型（降级后为备用模型）；`usage` 可能在中途或最后一个 chunk 才出现；`reasoning` 会随消息落库，刷新后可回放。`web_search` 默认 `true`，关闭后不会给上游传搜索参数。

### 5.3 停止生成

```
前端 AbortController 中断 fetch
  → 后端 request.is_disconnected() 检测到
  → 停止拉取上游（避免继续计费）
  → 已生成内容与思考过程以 status=aborted 落库
```

### 5.4 登出与强制下线

| 场景 | 机制 |
|---|---|
| 主动登出 | 当前 token 的 `jti` 写入 `revoked_tokens`，只撤销当前会话 |
| 管理员禁用 | `status=disabled` 且 `token_version += 1`，该用户所有 token 立即失效 |
| 管理员重置密码 | 密码哈希更新且 `token_version += 1`，旧 token 全部失效 |
| 管理员删除 | 软删 `deleted_at`、`status=disabled`、`token_version += 1` |
| 用户自己改密码 | `token_version += 1`，其他设备全部下线 |

### 5.5 管理后台

```
GET  /api/admin/users          用户列表（搜索 / 状态筛选 / 分页 / 会话与消息计数）
PATCH /api/admin/users/{id}    启用 / 禁用
POST /api/admin/users/{id}/reset-password
DELETE /api/admin/users/{id}   软删除
GET  /api/admin/stats          用户 / 会话 / 消息统计
GET  /api/admin/audit-logs     审计日志（搜索 / 分页）
```

所有管理接口都经过 `require_admin`；操作结果写入 `audit_logs`，但不记录密码、token 或聊天正文。

## 6. 数据模型

```sql
users
  id, username(UNIQUE), password_hash, nickname,
  role('user'|'admin'), status('active'|'disabled'),
  token_version, failed_login_attempts, locked_until,
  created_at, last_login_at, deleted_at

conversations
  id, user_id(FK), title, model_id, system_prompt,
  voice_type, voice_prompt,
  summary, summary_until_id,
  created_at, updated_at, deleted_at

messages
  id, conversation_id(FK), role('user'|'assistant'),
  content, reasoning, model_id,
  input_tokens, output_tokens, latency_ms,
  status('streaming'|'done'|'aborted'|'error'),
  attachments(JSON, 预留多模态), created_at

personas
  id, user_id(FK), name, prompt, description,
  voice_type, voice_prompt, created_at, updated_at, deleted_at

custom_voices
  id, user_id(FK), voice_id(UNIQUE), name, prompt,
  target_model, preview_text, created_at, deleted_at

revoked_tokens
  id, jti(UNIQUE), expires_at, created_at

audit_logs
  id, actor_id, actor_username, action, target_type, target_id,
  detail(JSON), ip, created_at
```

**设计要点**

| 点 | 理由 |
|---|---|
| 用户/会话软删（`deleted_at`） | 保留数据，后续做回收站/审计不用改表；`messages` 无 `deleted_at`，随会话级联 |
| `messages.status` | 必须能区分"已停止"和"失败"，否则前端提示不准 |
| `messages.reasoning` | 推理模型的思考过程可回放，不再刷新即丢 |
| `conversations.system_prompt` | 会话级人设；为空时回退到全局默认 |
| `conversations.summary` / `summary_until_id` | 早期对话的滚动摘要，以及已被摘要到的消息 id；避免把旧消息无限塞进上下文 |
| `personas` 独立存储 | 角色可跨会话复用；应用时把 prompt、音色与音色描述复制到会话 |
| `voice_type` / `voice_prompt` | `voice_type` 是百炼 TTS 的 voice 参数；`voice_prompt` 记录期望音色特征 |
| `custom_voices` | 保存声音设计生成的自定义音色、绑定模型和描述；按用户隔离 |
| 时间统一 UTC | 自定义 `UTCDateTime` 类型，读出来强制带 `+00:00`，避免前端差 8 小时 |
| 不建用量表 | 统计由 messages 聚合得出，当前量级够用 |
| JSON `attachments` | 为将来多模态预留，现在零成本 |
| 审计不存正文 | 只记录操作元数据，避免隐私泄露 |
| 轻量迁移 | `init_db()` 建新表，并对旧 SQLite 表幂等补列 |

索引：`conversations(user_id, updated_at)`、`messages(conversation_id, created_at)`、`personas(user_id, updated_at)`、`custom_voices(user_id, created_at)`、`revoked_tokens(jti)`、`audit_logs(created_at)`。

## 8. SSE 协议

| 事件 | 数据 | 说明 |
|---|---|---|
| `meta` | `{message_id, conversation_id, model_id, context_tokens, summarized_messages}` | 首个事件；`model_id` 是**实际使用**的模型，后两个字段用于前端展示上下文用量 |
| `delta` | `{text}` | 正文增量 |
| `reasoning` | `{text}` | 思考过程（推理模型才有），会落库 |
| `usage` | `{input_tokens, output_tokens}` | token 用量，会落库 |
| `done` | `{finish_reason}` | 正常结束 |
| `error` | `{code, message}` | 生成中途出错 |

前端用 `fetch` + `ReadableStream` 解析（`EventSource` 只支持 GET，带不了请求体）。

## 9. 架构与分层

```
React 19 (Vite)  ──HTTP/SSE，经 Vite 代理──▶  FastAPI
                                              ├─ Auth（JWT + jti 黑名单 + token_version + 登录锁定）
                                              ├─ Chat（隔离校验 / 上下文预算 / 落库 / 降级）
                                              ├─ Admin（require_admin / 用户操作 / 审计）
                                              ├─ System（公开配置）
                                              ├─ Provider Adapter（OpenAI 兼容，chunk 归一化）
                                              ├─ Registry（models.yaml → provider + key）
                                              └─ SQLite（SQLAlchemy 2.0 + WAL）
                                                   ↓ HTTPS 流式
                                    DeepSeek / 阿里云百炼 / 火山方舟

生产模式：FastAPI 同时托管 frontend/dist，SPA 路由回退到 index.html
```

**依赖方向单向**：

```
routers → core / services → db / providers
```

| 层 | 只做 | 不做 |
|---|---|---|
| `routers` | 参数解析、鉴权依赖、返回 schema | 不直接写 SQL |
| `core` | 配置、鉴权依赖、权限、错误码、日志、密码与 JWT | 不含业务规则 |
| `services` | 语音、审计、启动引导等可复用业务 | 不拼 HTTP 响应 |
| `db` | 引擎、会话、ORM 表结构、启动补列 | 不含业务判断 |
| `providers` | 上游调用、chunk 归一化、错误映射 | 不知道用户是谁 |

## 10. 非功能设计

| 维度 | 实现 |
|---|---|
| 密码 | bcrypt；统一截断到 72 字节（bcrypt 上限） |
| 令牌 | JWT HS256，7 天；`ver` 强制下线；`jti` 单 token 撤销 |
| 登录保护 | 默认连续失败 5 次锁定 15 分钟，可配置 |
| 错误 | 统一 `{error:{code,message,request_id,detail}}`；24 个错误码分五组 |
| 日志 | 结构化（ts/level/request_id/user_id/event），按天轮转保留 14 天 |
| 审计 | 认证与管理操作写入 `audit_logs`，可按操作者/动作/目标查询 |
| 隐私 | 日志与审计**不记录**聊天正文、密码、token、key |
| 超时 | 上游连接 10s、总时长 120s，超时返回 `MODEL_TIMEOUT` |
| 中断 | 客户端断开即取消上游，已生成内容与 reasoning 落库为 `aborted` |
| 并发 | SQLite + WAL + busy_timeout 5s |
| 时区 | 存储 UTC，出口带时区，前端直接可用 |
| 健康检查 | `/health` 含 DB 探活，异常返回 degraded |
| 请求追踪 | 每个请求生成 12 位 `request_id`，写入响应头与全部日志 |
| 上下文预算 | 10 轮 + 24000 字符，从最新消息往前累加，至少保留最新一条 |
| 生产托管 | `frontend/dist` 存在时自动挂载静态资源并回退 SPA |
| 数据迁移 | 启动时对旧库幂等补列，无需手工改表 |
| 角色美化 | 使用 `PERSONA_MODEL_ID`，走 fallback 链，结果截断到 4000 字符 |
| 语音 | 百炼 Qwen3-ASR-Flash 识别 + Qwen3-TTS 合成；TTS 单次最多 1200 字符，超出截断 |
| 音色 | 默认只保留 Cherry 一个系统音色；未选择时使用 `DEFAULT_VOICE_TYPE` |
| 自定义音色 | 声音设计绑定 `qwen-audio-3.1-tts-flash`；创建免费，合成按量计费 |
| 视觉主题 | 白色/浅灰背景；蓝色主操作、琥珀色警示、红色危险操作 |

### 11.2 联网搜索

| 项 | 规则 |
|---|---|
| 默认模型 | `DEFAULT_MODEL_ID=qwen3.8-flash`，前端首次进入优先选中它 |
| 开关 | 聊天页「联网：开/关」，默认开；仅对支持搜索的模型生效 |
| 请求参数 | `enable_search: true` + `search_options: {forced_search: false, search_strategy: turbo, enable_source: true}` |
| 检索时机 | `forced_search=false`：闲聊不搜，问天气/新闻等实时信息才检索 |
| 能力声明 | `models.yaml` 的 `search: true` → `/api/models` 返回 `supports_search`；客户端下拉显示「· 联网」 |
| 降级 | 备用模型不支持搜索时不传搜索参数，不会因此报错 |
| 实测 | 「你好」prompt 62 tokens（未检索）；「郑州今天天气」prompt 3290 tokens（已检索），回答给出当日气温 |

### 11.3 降级策略

| 项 | 规则 |
|---|---|
| 触发时机 | **仅限第一个 token 之前** |
| 触发条件 | 连接失败 / 超时 / 429 / 密钥无效 / 模型未开通 |
| 已开始输出 | 不切换（避免一条回答前后风格不一致） |
| 可观测 | 日志 `event=model_fallback`，记录 from/to/reason |
| 用户感知 | 无感；`meta.model_id` 为实际使用模型 |

**降级必须跨供应商**：同厂商限流时旗下模型通常一起限，自己兜底无意义。

## 13. 已知限制

| 限制 | 说明 | 风险 |
|---|---|---|
| 无用量限额 | 注册即可无限调用 | 高（成本） |
| 上下文按轮数+字符截断 | 10 轮 / 24000 字符，不按 token 精算，超长仍可能被上游拒绝 | 中 |
| 搜索使用 LIKE | 无全文索引，数据量大时性能下降 | 中 |
| SQLite 单文件 | 不能多进程/多机部署 | 低（当前单机） |
| 会话标题 | 取首条消息前 20 字，非模型生成 | 低 |
| 审计覆盖有限 | 只记录认证与管理操作，不含会话增删改查 | 低 |
| 旧 token 无 jti | 升级前签发的 token 没有 jti，登出不会立即撤销，最长持续 7 天 | 低（过渡期） |
| 无自助找回密码 | 只能由管理员重置 | 低 |
| 前端单包偏大 | 构建产物约 631KB，未做路由级代码分割 | 低 |
| 语音依赖百炼额度 | Qwen3-TTS/ASR 需要百炼 Key 与模型额度，额度耗尽或限流时会失败 | 中 |
| TTS 长度上限 | 单次朗读最多 1200 字符，超出部分截断 | 低 |
| 录音非实时 | 录音停止后才上传识别，不是边说边转写 | 低 |
| 自定义音色配额 | 百炼账号最多 1000 个自定义音色，声音复刻与声音设计共用配额 | 中 |
| 音色绑定模型 | 自定义音色创建时绑定 `qwen-audio-3.1-tts-flash`，后续合成必须使用同一模型 | 低 |
| 音色描述长度 | `voice_prompt` 最多 500 字；预览文本需 15-200 字 | 低 |
| 角色应用是快照 | 应用角色时复制 prompt 到会话，后续修改角色不会自动同步已应用的会话 | 低 |
| 提示词美化依赖模型 | 模型不可用或限流时美化失败，需要手动编写 | 低 |

cd frontend

## 16. 功能模块实现逻辑

### 16.1 启动与请求生命周期

1. `app/main.py` 在创建 app **之前**调用 `setup_logging`，避免启动阶段日志丢失。
2. lifespan 顺序：`init_db()`（`create_all` 建新表 + `_migrate_sqlite` 幂等补列）→ `ensure_seed_admin()` → `cleanup_revoked_tokens()`；关闭时 `dispose_db()`。
3. HTTP 中间件为每个请求生成 `request_id`，写入响应头 `X-Request-Id`，记录方法、路径、状态码、耗时；未捕获异常统一返回 500 错误体。
4. CORS 最后注册（最外层），保证错误响应也带 CORS 头。
5. 挂载 8 个 router；`/health` 执行 `SELECT 1` 探活，失败返回 `degraded`。
6. `frontend/dist/index.html` 存在时挂载 `/assets` 与 SPA 回退；开发期由 Vite 把 `/api` 代理到 `127.0.0.1:8000`。

### 16.2 配置与模型注册

- 配置优先级：环境变量 > `.env` > `Settings` 代码默认值；`get_settings()` 带缓存。
- `BASE_DIR` 定义在 `app/core/config.py`，取当前文件向上三级 → 项目根；SQLite 相对路径据此转绝对路径，避免"从哪个目录启动"决定库位置。
- `config/models.yaml` 字段：`id`、`name`、`fallback`、`search`、`hidden`；provider 级：`enabled`、`base_url`、`api_key_env`、`stream_options`。
- `registry.list_models()`：跳过 `enabled: false` 的 provider 和 `hidden: true` 的模型；密钥存在才 `available`；同时给出 `is_default`（对比 `DEFAULT_MODEL_ID`）与 `supports_search`。
- `registry.resolve()`：找不到模型 → `MODEL_NOT_FOUND`；provider 无密钥 → `MODEL_KEY_MISSING`；每次按 provider 配置构造 `OpenAICompatibleProvider`。
- `registry.fallback_chain()`：返回 `[主模型, 备用...]`，`fallback` 支持字符串或列表，去重。

### 16.3 鉴权、权限与隔离

- **注册**：`ALLOW_REGISTRATION=false` 时直接拒绝；用户名正则 `^[A-Za-z0-9_]{3,20}$`；密码 bcrypt（统一截断 72 字节）。
- **登录**：用户不存在与密码错误返回同一错误，避免用户名枚举；累计失败达到阈值锁定 N 分钟；锁定过期自动清零；`status != active` 拒绝登录；成功后写审计并记录 `last_login_at`。
- **令牌**：JWT HS256，载荷含 `sub`（用户 id）、`ver`（`token_version`）、`jti`、`exp`。
- **依赖校验**（`app/core/deps.py`）：解析 token → 查黑名单 `jti` → 比对 `ver` 与 `user.token_version` → 校验账号状态；任一失败即 401。
- **隔离红线**：`OwnConversation` 只按 `user_id + id` 查，别人的资源一律 404（不是 403，避免泄露"存在但无权"）。
- **登出**：当前 token 的 `jti` 写入 `revoked_tokens` 并带过期时间；改密码、管理员禁用/重置/删除会提升 `token_version`，旧 token 全失效。

### 16.4 会话与消息

- 列表：按当前用户过滤 + 软删过滤，`q` 同时匹配会话标题与消息正文（`EXISTS` 子查询），按 `updated_at desc, id desc` 排序并分页。
- 新建：未指定模型用 `DEFAULT_MODEL_ID`，并校验模型在配置中已知。
- 更新：改名、换模型（再次校验）、改会话人设/音色；`system_prompt` 传空串表示清除。
- 删除：软删 `deleted_at`，消息保留。
- 导出：按消息顺序拼 Markdown；消息列表含 `reasoning` 与 token 用量。

### 16.5 流式对话（SSE）

1. 校验内容非空、不超 `MAX_MESSAGE_CHARS`，校验会话归属。
2. 用户消息先落库并提交（中途断开问题不丢），首条消息用前 20 字生成标题，刷新 `updated_at`。
3. `_build_context`：系统提示词（会话人设 > 全局默认）+ 历史摘要 + 最近 `MAX_CONTEXT_TURNS` 轮；从最新往前累加，受 `MAX_CONTEXT_TOKENS` 估算预算约束，至少保留最新一条用户消息。
4. 按 fallback 链逐个 `_open_stream`，第一个 chunk 到手即选定；切换时记 `event=model_fallback`。
5. 建 `status=streaming` 的 assistant 占位消息，先发 `meta`；随后 `delta` / `reasoning` / `usage` / `done`。
6. 客户端断开通过 `request.is_disconnected()` 检测，停止拉取上游；已生成内容以 `aborted` 落库。
7. 生成失败发 `error` 并以 `error` 状态落库；结束统一回写内容、思考过程、tokens、耗时。
8. 回答结束后异步触发滚动摘要，不增加首字延迟。

#### 16.5.1 上下文预算与滚动摘要

**Token 估算**：`app/core/tokens.py` 按「中文/中文标点 1 字≈1 token，其他字符 4 个≈1 token」估算，避免字符预算与上游窗口不对应。

**摘要触发与写入**（`_maybe_summarize`）：

1. 只统计 `id > summary_until_id` 且内容非空的 user/assistant 消息。
2. 估算 token 超过 `SUMMARY_TRIGGER_TOKENS` 才压缩；消息条数不足 `SUMMARY_KEEP_MESSAGES` 时不动。
3. 保留最近 `SUMMARY_KEEP_MESSAGES` 条原文，把更早的部分拼成转录文本（单次最多 16000 字符），连同已有摘要交给 `SUMMARY_MODEL_ID` 的 fallback 链生成新摘要（≤800 字符）。
4. 成功后写回 `summary` 与 `summary_until_id`；失败只记 `event=summary_failed`，不影响本轮回答，下次再试。
5. 摘要任务在 SSE 结束后 `asyncio.create_task` 执行，并用全局锁串行化，避免同一会话并发压缩。

**组装规则**：摘要以 `【此前对话摘要】` 追加在系统提示词后；`summary_until_id` 之前的消息不再发送，之后的最近若干条按原文发送。这样长会话的上下文始终由「人设 + 摘要 + 最近原文」构成，而不是无限增长或直接丢掉最旧内容。

**前端展示**：`meta.context_tokens` 与 `meta.summarized_messages` 由前端显示为「上下文 ≈ x tokens（已压缩 y 条）」。

**兜底**：摘要模型不可用、摘要为空或写入失败时，行为退化为按 token 预算截断，不影响对话可用性。

### 16.6 联网搜索

- `_open_stream` 仅在 `web_search=true` 且模型配置 `search: true` 时附加：
  `enable_search: true` + `search_options: {forced_search: false, search_strategy: turbo, enable_source: true}`。
- `forced_search: false` 表示由模型判断是否检索：闲聊不搜，天气/新闻等实时问题才搜。
- 降级链中逐个模型独立判断能力，备用模型不支持搜索时不会带参数。
- 前端：默认模型优先选 `is_default`；下拉框给 `supports_search` 的模型加「· 联网」；顶部「联网：开/关」控制 `web_search`，默认开。

### 16.7 角色设定与提示词美化

- `Persona` 按用户隔离，CRUD 均为软删；`name + prompt` 必填，`voice_type` / `voice_prompt` 可选。
- 提示词美化：`_generate` 按 `PERSONA_MODEL_ID` 的 fallback 链逐个尝试，`temperature=0.7`，流式收集后拼接。
- `_clean_prompt` 去掉 Markdown 代码围栏，限制 4000 字，防止模型输出包裹格式。
- 音色描述生成：以角色提示词为输入，生成包含性别、年龄感、音色、语速、语调、情绪的描述。
- 前端 `PersonaDialog`：选择已有角色或新建 → 可手动写提示词 → 一键美化并可继续编辑 → 选择音色或生成自定义音色 → 保存并应用（写入角色库 + 当前会话 `system_prompt/voice_type/voice_prompt`）。

### 16.8 语音输入与朗读

- **TTS**：`synthesize_speech` 截断到 `MAX_TTS_CHARS` → 按标点分段 → 逐段调用 → WAV 归一化后拼接 PCM。
- 模型分流：`qwen-audio-*` 走 `SpeechSynthesizer`；其余（如 `qwen3-tts-flash`）走 multimodal-generation。上游返回 base64 或 URL，均转成字节。
- **自定义音色**：`design_voice` 调 `voice-enrollment` 的 `create_voice`，绑定 `BAILIAN_DESIGN_TTS_MODEL`，返回 `voice_id` 与预览音频并入库 `custom_voices`。
- **TTS 路由**：`voice_type` 是默认音色则用默认 TTS 模型；否则查当前用户的自定义音色并改用其 `target_model`，查不到返回 `VOICE_NOT_FOUND`。
- **ASR**：接收 multipart 音频，转 Base64 Data URL 调 `qwen3-asr-flash` 的 OpenAI 兼容接口。
- **前端**：`Composer` 用 `getUserMedia + AudioContext + ScriptProcessor` 录音，重采样 16k、编码 WAV 后上传；`utils/speech.ts` 用 AudioContext 播放服务端音频，规避浏览器自动播放限制，并在用户手势时 `unlockAudio()`。

### 16.9 管理后台与审计

- 管理接口统一用 `AdminUser` 依赖（`role=admin`）。
- 用户列表支持关键词（用户名/昵称）、状态过滤、分页，并统计会话数/消息数。
- 禁用/启用、重置密码、软删都会 `token_version += 1`，让目标用户旧 token 立即失效。
- 保护规则：不能改自己的状态、不能给自己重置密码、不能删除自己、不能删除管理员账号。
- 统计：用户总数/活跃/禁用、会话数、消息数、今日消息数。
- 审计：`write_audit` 只记动作、操作者、目标、IP、时间；不记录密码、token、聊天正文。管理员没有任何查看他人聊天内容的接口。

### 16.10 前端实现

- `App.tsx` 负责路由与登录守卫；`store/auth.ts` 持久化 token/user。
- `api.ts` 统一注入 Bearer token；401 清理登录态并广播 `aiqa:unauthorized`；`streamChat` 用 `fetch + ReadableStream` 手工解析 SSE（`EventSource` 不支持 POST）。
- `ChatPage` 集中管理模型、会话、消息、流式状态与 AbortController：发送时先插入临时用户消息与占位助手消息，按 `delta` 增量更新，`done/error/aborted` 落状态，最后拉取服务端消息对齐真实 id。
- 会话切换、搜索、新建、改名、删除、导出都在该页编排；角色、音色、自动朗读、联网开关也在页头控制。
- `MessageBubble` 负责 Markdown 渲染、复制、单条朗读；`Composer` 负责输入、字数限制、语音输入；`AdminPage` 负责用户管理与审计查看。

### 16.11 数据模型与迁移

- 主要表：`users`、`personas`、`custom_voices`、`conversations`、`messages`、`revoked_tokens`、`audit_logs`。
- 时间统一以 UTC 存储（`UTCDateTime`），展示时由前端本地化。
- 用户、会话、角色、自定义音色均软删（`deleted_at`），登录与查询都过滤软删数据。
- 启动迁移：`_migrate_sqlite` 用 `ALTER TABLE` 补 `users.failed_login_attempts/locked_until`、`conversations.system_prompt/voice_type/voice_prompt/summary/summary_until_id`、`personas.voice_type/voice_prompt`、`messages.reasoning`；并清理不在 `custom_voices` 里的历史系统音色。
- SQLite 每次连接启用 `foreign_keys` 与 WAL，兼顾外键约束与并发读。
