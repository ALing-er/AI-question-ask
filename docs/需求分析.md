### 已落地的红线

1. **管理员不可见聊天内容** —— 不是 UI 隐藏，是**根本不提供该接口**。
2. **管理员不能对自己执行禁用/删除/重置密码**，也不能删除管理员账号。
3. **角色固定** —— 注册一律 `user`；管理员只来自 `.env` 种子账号，界面无提权入口。
4. **权限在服务端校验** —— 前端隐藏按钮只是体验优化。

## 5. 核心流程

### 5.1 注册 / 登录

```
POST /api/auth/register  {username, password}
  → 检查 ALLOW_REGISTRATION 开关
  → 格式校验（用户名 3-20 位字母数字下划线；密码 ≥8）
  → 唯一性校验（唯一索引兜底并发）
  → bcrypt 哈希 → 落库(role=user, status=active, token_version=0)
  → 写审计日志 → 直接签发 JWT（注册即登录）

POST /api/auth/login
  → 用户不存在 与 密码错误 统一返回 401（防用户名枚举）
  → 锁定未过期 → 429 AUTH_LOGIN_LOCKED
  → 密码错误 → 失败计数 +1；达到 5 次锁定 15 分钟
  → 被禁用返回 403 AUTH_USER_DISABLED
  → 成功 → 清空失败计数、更新 last_login_at、写审计 → 签发 JWT
```

JWT payload：`sub` / `role` / `ver` / `jti` / `iat` / `exp`，有效期 7 天。

### 5.2 流式对话（含降级）

```
POST /api/chat/stream  {conversation_id, content, model_id?}
  → 校验内容非空且不超过 MAX_MESSAGE_CHARS
  → 校验会话归属（非本人 404）
  → 校验主模型可解析（不可解析直接 404）
  → 用户消息落库 + 首条消息自动生成标题 + 刷新会话 updated_at
  → 系统提示词 = 会话 system_prompt，否则 DEFAULT_SYSTEM_PROMPT
  → 组装上下文（系统提示词 + 最近 10 轮，受 MAX_CONTEXT_CHARS 预算约束）
  → 按 fallback 链依次尝试打开上游流：
        第一个 chunk 到手 → 选定该模型
        失败（连接/超时/429/密钥/未开通） → 试下一个
  → 建 assistant 占位消息(status=streaming) → 发 meta
  → 逐 chunk 转 SSE 下发（delta / reasoning）
  → 结束回写同一条消息（content + reasoning + tokens + latency）
```

补充：`meta.model_id` 是实际使用的模型（降级后为备用模型）；`usage` 可能在中途或最后一个 chunk 才出现；`reasoning` 会随消息落库，刷新后可回放。

### 5.3 停止生成

```
前端 AbortController 中断 fetch
  → 后端 request.is_disconnected() 检测到
  → 停止拉取上游（避免继续计费）
  → 已生成内容与思考过程以 status=aborted 落库
```

### 5.4 登出与强制下线

| 场景 | 机制 |
|---|---|
| 主动登出 | 当前 token 的 `jti` 写入 `revoked_tokens`，只撤销当前会话 |
| 管理员禁用 | `status=disabled` 且 `token_version += 1`，该用户所有 token 立即失效 |
| 管理员重置密码 | 密码哈希更新且 `token_version += 1`，旧 token 全部失效 |
| 管理员删除 | 软删 `deleted_at`、`status=disabled`、`token_version += 1` |
| 用户自己改密码 | `token_version += 1`，其他设备全部下线 |

### 5.5 管理后台

```
GET  /api/admin/users          用户列表（搜索 / 状态筛选 / 分页 / 会话与消息计数）
PATCH /api/admin/users/{id}    启用 / 禁用
POST /api/admin/users/{id}/reset-password
DELETE /api/admin/users/{id}   软删除
GET  /api/admin/stats          用户 / 会话 / 消息统计
GET  /api/admin/audit-logs     审计日志（搜索 / 分页）
```

所有管理接口都经过 `require_admin`；操作结果写入 `audit_logs`，但不记录密码、token 或聊天正文。

## 6. 数据模型

```sql
users
  id, username(UNIQUE), password_hash, nickname,
  role('user'|'admin'), status('active'|'disabled'),
  token_version, failed_login_attempts, locked_until,
  created_at, last_login_at, deleted_at

conversations
  id, user_id(FK), title, model_id, system_prompt,
  created_at, updated_at, deleted_at

messages
  id, conversation_id(FK), role('user'|'assistant'),
  content, reasoning, model_id,
  input_tokens, output_tokens, latency_ms,
  status('streaming'|'done'|'aborted'|'error'),
  attachments(JSON, 预留多模态), created_at

personas
  id, user_id(FK), name, prompt, description,
  created_at, updated_at, deleted_at

revoked_tokens
  id, jti(UNIQUE), expires_at, created_at

audit_logs
  id, actor_id, actor_username, action, target_type, target_id,
  detail(JSON), ip, created_at
```

**设计要点**

| 点 | 理由 |
|---|---|
| 用户/会话软删（`deleted_at`） | 保留数据，后续做回收站/审计不用改表；`messages` 无 `deleted_at`，随会话级联 |
| `messages.status` | 必须能区分"已停止"和"失败"，否则前端提示不准 |
| `messages.reasoning` | 推理模型的思考过程可回放，不再刷新即丢 |
| `conversations.system_prompt` | 会话级人设；为空时回退到全局默认 |
| `personas` 独立存储 | 角色可跨会话复用；应用时把 prompt 复制到 `conversation.system_prompt` |
| 时间统一 UTC | 自定义 `UTCDateTime` 类型，读出来强制带 `+00:00`，避免前端差 8 小时 |
| 不建用量表 | 统计由 messages 聚合得出，当前量级够用 |
| JSON `attachments` | 为将来多模态预留，现在零成本 |
| 审计不存正文 | 只记录操作元数据，避免隐私泄露 |
| 轻量迁移 | `init_db()` 建新表，并对旧 SQLite 表幂等补列 |

索引：`conversations(user_id, updated_at)`、`messages(conversation_id, created_at)`、`personas(user_id, updated_at)`、`revoked_tokens(jti)`、`audit_logs(created_at)`。

## 8. SSE 协议

| 事件 | 数据 | 说明 |
|---|---|---|
| `meta` | `{message_id, conversation_id, model_id}` | 首个事件；`model_id` 是**实际使用**的模型 |
| `delta` | `{text}` | 正文增量 |
| `reasoning` | `{text}` | 思考过程（推理模型才有），会落库 |
| `usage` | `{input_tokens, output_tokens}` | token 用量，会落库 |
| `done` | `{finish_reason}` | 正常结束 |
| `error` | `{code, message}` | 生成中途出错 |

前端用 `fetch` + `ReadableStream` 解析（`EventSource` 只支持 GET，带不了请求体）。

## 9. 架构与分层

```
React 19 (Vite)  ──HTTP/SSE，经 Vite 代理──▶  FastAPI
                                              ├─ Auth（JWT + jti 黑名单 + token_version + 登录锁定）
                                              ├─ Chat（隔离校验 / 上下文预算 / 落库 / 降级）
                                              ├─ Admin（require_admin / 用户操作 / 审计）
                                              ├─ System（公开配置）
                                              ├─ Provider Adapter（OpenAI 兼容，chunk 归一化）
                                              ├─ Registry（models.yaml → provider + key）
                                              └─ SQLite（SQLAlchemy 2.0 + WAL）
                                                   ↓ HTTPS 流式
                                    DeepSeek / 阿里云百炼 / 火山方舟

生产模式：FastAPI 同时托管 frontend/dist，SPA 路由回退到 index.html
```

**依赖方向单向**：

```
routers → deps/services → providers / ORM
```

| 层 | 只做 | 不做 |
|---|---|---|
| `routers` | 参数解析、鉴权依赖、返回 schema | 不直接写 SQL |
| `deps` | 身份、权限、资源归属、token 黑名单 | 不含业务规则 |
| `providers` | 上游调用、chunk 归一化、错误映射 | 不知道用户是谁 |
| `models` | 纯表结构 | 不含业务判断 |

## 10. 非功能设计

| 维度 | 实现 |
|---|---|
| 密码 | bcrypt；统一截断到 72 字节（bcrypt 上限） |
| 令牌 | JWT HS256，7 天；`ver` 强制下线；`jti` 单 token 撤销 |
| 登录保护 | 默认连续失败 5 次锁定 15 分钟，可配置 |
| 错误 | 统一 `{error:{code,message,request_id,detail}}`；24 个错误码分五组 |
| 日志 | 结构化（ts/level/request_id/user_id/event），按天轮转保留 14 天 |
| 审计 | 认证与管理操作写入 `audit_logs`，可按操作者/动作/目标查询 |
| 隐私 | 日志与审计**不记录**聊天正文、密码、token、key |
| 超时 | 上游连接 10s、总时长 120s，超时返回 `MODEL_TIMEOUT` |
| 中断 | 客户端断开即取消上游，已生成内容与 reasoning 落库为 `aborted` |
| 并发 | SQLite + WAL + busy_timeout 5s |
| 时区 | 存储 UTC，出口带时区，前端直接可用 |
| 健康检查 | `/health` 含 DB 探活，异常返回 degraded |
| 请求追踪 | 每个请求生成 12 位 `request_id`，写入响应头与全部日志 |
| 上下文预算 | 10 轮 + 24000 字符，从最新消息往前累加，至少保留最新一条 |
| 生产托管 | `frontend/dist` 存在时自动挂载静态资源并回退 SPA |
| 数据迁移 | 启动时对旧库幂等补列，无需手工改表 |
| 角色美化 | 使用 `PERSONA_MODEL_ID`，走 fallback 链，结果截断到 4000 字符 |
| 语音 | 浏览器 Web Speech API；语音输入与朗读依赖浏览器/系统语音包 |
| 视觉主题 | 白色/浅灰背景；蓝色主操作、琥珀色警示、红色危险操作 |

## 11. 模型接入与降级

### 11.1 当前供应商

| 供应商 | 模型 | 状态 |
|---|---|---|
| DeepSeek | `deepseek-chat`、`deepseek-reasoner` | ✅ |
| 阿里云百炼 | `qwen3.8-max`、`qwen3.8-flash`、`deepseek-v4-pro-0813`、`kimi-k3` | ✅ |
| 火山方舟 | 豆包 Seed 2.1 Pro / Turbo | ⚠️ key 有效，模型未开通 |

### 11.2 降级策略

| 项 | 规则 |
|---|---|
| 触发时机 | **仅限第一个 token 之前** |
| 触发条件 | 连接失败 / 超时 / 429 / 密钥无效 / 模型未开通 |
| 已开始输出 | 不切换（避免一条回答前后风格不一致） |
| 可观测 | 日志 `event=model_fallback`，记录 from/to/reason |
| 用户感知 | 无感；`meta.model_id` 为实际使用模型 |

**降级必须跨供应商**：同厂商限流时旗下模型通常一起限，自己兜底无意义。

## 13. 已知限制

| 限制 | 说明 | 风险 |
|---|---|---|
| 无用量限额 | 注册即可无限调用 | 高（成本） |
| 上下文按轮数+字符截断 | 10 轮 / 24000 字符，不按 token 精算，超长仍可能被上游拒绝 | 中 |
| 搜索使用 LIKE | 无全文索引，数据量大时性能下降 | 中 |
| SQLite 单文件 | 不能多进程/多机部署 | 低（当前单机） |
| 会话标题 | 取首条消息前 20 字，非模型生成 | 低 |
| 审计覆盖有限 | 只记录认证与管理操作，不含会话增删改查 | 低 |
| 旧 token 无 jti | 升级前签发的 token 没有 jti，登出不会立即撤销，最长持续 7 天 | 低（过渡期） |
| 无自助找回密码 | 只能由管理员重置 | 低 |
| 前端单包偏大 | 构建产物约 631KB，未做路由级代码分割 | 低 |
| 语音依赖浏览器 | 语音输入/朗读基于 Web Speech API，部分浏览器或系统无中文语音包时不可用或音色受限 | 中 |
| 角色应用是快照 | 应用角色时复制 prompt 到会话，后续修改角色不会自动同步已应用的会话 | 低 |
| 提示词美化依赖模型 | 模型不可用或限流时美化失败，需要手动编写 | 低 |

## 14. 启动与部署

### 开发模式

一键启动（推荐）：

```
双击 start.bat
```

脚本会检查 Python / Node、自动安装依赖、校验 8000 / 5173 端口，分别启动前后端并打开浏览器。

手动启动：

```powershell
# 后端
.\.venv\Scripts\Activate.ps1
python -m uvicorn app.main:app --reload --port 8000

# 前端
cd frontend
npm run dev
```

### 生产模式

```powershell
cd frontend
npm run build

cd ..
python -m uvicorn app.main:app --port 8000
```

`frontend/dist/index.html` 存在时，FastAPI 会自动托管静态资源与 SPA 路由；不存在时只提供 API。

### 新增配置项

| 配置 | 默认值 | 说明 |
|---|---|---|
| `ALLOW_REGISTRATION` | `true` | 是否开放自助注册 |
| `LOGIN_MAX_ATTEMPTS` | `5` | 连续失败多少次锁定 |
| `LOGIN_LOCK_MINUTES` | `15` | 锁定分钟数 |
| `MAX_MESSAGE_CHARS` | `8000` | 单条消息最大字符数 |
| `MAX_CONTEXT_CHARS` | `24000` | 上下文字符预算 |
| `DEFAULT_SYSTEM_PROMPT` | 空 | 会话未单独设置人设时的全局默认 |
| `PERSONA_MODEL_ID` | `deepseek-chat` | 角色提示词美化使用的模型 |
| `FRONTEND_DIST` | `frontend/dist` | 生产前端产物目录 |

种子管理员仍由 `.env` 的 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 在启动时创建；账号已存在时不会覆盖密码。
